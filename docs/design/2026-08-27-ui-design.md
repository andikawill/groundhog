# UI design — tokens, status, screens

- **Date:** 2026-08-27
- **Status:** ready to implement
- **Stylesheet:** [`app/globals.css`](../../app/globals.css)
- **Information architecture it honours:** `docs/superpowers/specs/2026-08-20-api-test-cycle-agent-design.md`,
  section `## UI` (that file is gitignored; the parts this document depends on are quoted or
  restated below so this one still reads without it)

There is no visual design in the tree today — `RunView.tsx` and `EnvsView.tsx` carry inline
styles. This document is the design; the stylesheet is the tokens and classes it names.
Neither touches a component.

**First implementation step:** add `import './globals.css'` to `app/layout.tsx`, drop the
inline `style` on `<body>`, then convert one region at a time. Inline styles win over every
class in the stylesheet, so a half-converted screen is not a broken screen — it is an
unconverted one.

## Constraints this was designed inside

No new dependency: no Tailwind, no component library, no icon package, no webfont. One
stylesheet, built on custom properties. System font stack; `ui-monospace` for payloads,
seeds and keys. Desktop-first, unbroken at 1280px, mobile ignored. Light and dark, both
designed. Status never carried by colour alone. Text contrast ≥ 4.5:1 in both themes.
Secrets appear only as `***` or `*** set`.

Two consequences worth naming, because they are choices and not accidents:

- **`color-scheme: light dark` is declared on `:root`.** Native `<select>` popups, scrollbars,
  the text caret and form widget chrome then follow the theme with no styling at all. This is
  the whole reason no select needs to be rebuilt as a custom listbox.
- **`<details>`/`<summary>` is the disclosure everywhere** — the raw log rows, expandable
  request and response bodies. Open state, keyboard behaviour and screen-reader semantics
  come free, and no state has to survive a re-render.

## Where this departs from the spec, and why

Read this before the rest. The spec wins by default; each line below is either a placement
change or something the platform would not do.

1. **The authoring chat bar is a reserved slot, not a designed feature.** The spec puts a
   chat bar at the bottom of the case screen ("Bar chat di bagian bawah dipakai untuk
   menambah atau mengubah step, bukan sebagai pusat layar"). `CLAUDE.md` lists
   natural-language authoring under *deliberately absent*. The layout therefore reserves the
   footer row (`.composer`, full width, below both columns) so adding it later moves nothing;
   the conversation itself is not designed. This is the one place the two documents disagree
   and I have honoured the spec's geometry without inventing the spec's feature.
2. **Seed and anchor live in the rail, not the header.** The spec's header holds case name,
   seed, env dropdown and replay. At 1280px a 24-character ISO anchor plus four controls plus
   the project picker wraps the header. Seed and anchor are copy targets that want a
   monospace block with room around them, so they sit at the top of the left rail with the
   run status and the replay button. Everything the spec asked for is present; two items moved
   down one region.
3. **The guard marker in the env dropdown is only partly honoured.** The spec requires envs
   marked `confirm` or `readonly` to be visible in the env dropdown, not only on the Envs
   screen. A native `<option>` cannot carry a styled badge in any cross-browser way, and
   replacing the select with a custom listbox means JavaScript and an accessibility surface
   nobody asked for. Resolution: the guard goes into the option's **text** (`prod · readonly`)
   and a `.guard` chip is rendered beside the closed select, reflecting the current selection.
   The information is in the dropdown; only its typography is not.
4. **Empty matrix cells get a glyph as well as red.** The spec says red plus a count. Colour
   alone is not allowed here, so an empty cell also gets a dashed 2px border, the placeholder
   text `empty`, and a `!` marker element beside the input. A strengthening, not a change.
5. **Two things in the spec are designed although the element inventory omits them**, because
   the data already exists in `RunStep` and dropping them would be losing information the
   engine paid to collect: `trace` (the correlation headers — `x-request-id` and friends —
   which the spec's `## Log` section says to show per step) and `attempts` (shown only when
   greater than 1, which means a `retryUntil` step retried).
6. **The response body is not in the detail pane.** The spec puts method/URL, body sent and
   origins in the right column, and request/response bodies in the raw log panel. Followed
   exactly: the detail pane never shows the response, the log panel always can.

## Tokens

Every value below is a custom property on `:root`, redefined inside
`@media (prefers-color-scheme: dark)`. Ratios in the notes column are measured, not
estimated.

### Colour — surfaces and text

| property | light | dark | note |
|---|---|---|---|
| `--bg` | `#f7f7f5` | `#17181b` | page |
| `--surface` | `#ffffff` | `#1e1f23` | panes, cards, inputs |
| `--surface-2` | `#f1f1ee` | `#24262b` | table head, hover, chips, selected row |
| `--surface-sunken` | `#eceae5` | `#131417` | payload blocks, active button |
| `--line` | `#dcdcd6` | `#34363c` | hairline between rows — decorative only |
| `--line-strong` | `#8f8f88` | `#6b6e78` | control borders; 3.25:1 / 3.24:1 on `--surface` |
| `--fg` | `#1b1b19` | `#e6e7e9` | 16.1:1 / 14.4:1 on `--bg` |
| `--fg-muted` | `#5f5f59` | `#a5a8ae` | 6.0:1 / 7.5:1 — labels, meta, secondary text |
| `--fg-faint` | `#6e6e67` | `#93969d` | 4.8:1 / 6.0:1 — the floor. Nothing dimmer carries text |

The light theme is warm neutral (paper), the dark theme is cool neutral (screen), and dark
surfaces **rise** toward the viewer as elevation increases while light surfaces fall. That
is why the dark values are not the light values inverted: an inverted `#f1f1ee` would put
the table head *below* the page, which reads as a hole.

There is no `--fg-disabled` and no opacity-based dimming. Both produce text whose contrast
depends on what happens to be behind it. Dim text is `--fg-muted` or `--fg-faint`, and both
are measured.

### Colour — status and accent

Each status colour ships with a tint used only as a badge or row background behind that same
colour. Every pairing below is ≥ 5.5:1 in light and ≥ 6.8:1 in dark.

| property | light | dark | used by |
|---|---|---|---|
| `--pass` / `--pass-tint` | `#1c6b3c` / `#e2efe6` | `#67c58c` / `#16291d` | passed |
| `--fail` / `--fail-tint` | `#a62823` / `#fbe4e2` | `#f2908a` / `#301b1a` | failed, empty cell, unresolved origin, errors |
| `--warn` / `--warn-tint` | `#7d4c05` / `#fbedd4` | `#dfa856` / `#2e240f` | awaiting, `confirm` guard, truncated body, attempts |
| `--info` / `--info-tint` | `#1d5aa8` / `#e3ecfa` | `#84b3f2` / `#152438` | running, links, selection |
| `--halt` / `--halt-tint` | `#6337a0` / `#ece5f8` | `#bb9aec` / `#241d33` | interrupted, `readonly` guard, secret flag |
| `--link` | `var(--info)` | `var(--info)` | anchors |
| `--focus` | `#1d5aa8` | `#84b3f2` | focus ring, 6.4:1 / 8.2:1 on `--bg` |
| `--btn-solid-bg` / `--btn-solid-fg` | `#1b1b19` / `#f7f7f5` | `#e6e7e9` / `#17181b` | the one primary button |

There is no brand hue. The primary action is the ink colour on the paper colour — dark
button in light theme, light button in dark theme. A tool with one primary action per screen
does not need a brand colour to find it, and inventing one would be inventing a product
decision.

`--halt` doing double duty for *interrupted* and for the `readonly` guard is deliberate:
both mean "this stopped short of running". The secret flag borrows it for the same reason it
borrows nothing else — it is the only other state that means "held back".

### Type

| property | value | used for |
|---|---|---|
| `--font-ui` | `system-ui, -apple-system, 'Segoe UI', Roboto, Helvetica, Arial, sans-serif` | everything not a payload |
| `--font-mono` | `ui-monospace, SFMono-Regular, Menlo, Consolas, 'Liberation Mono', monospace` | payloads, seeds, ids, paths, tokens, env keys, status glyphs |
| `--fs-1` | `11px` | uppercase section labels, chips |
| `--fs-2` | `12px` | meta, log rows, dense monospace |
| `--fs-3` | `13px` | base |
| `--fs-4` | `15px` | pane heading |
| `--fs-5` | `18px` | screen title |
| `--lh-tight` / `--lh` / `--lh-mono` | `1.25` / `1.5` / `1.55` | headings / prose / monospace |
| `--fw` / `--fw-mid` / `--fw-bold` | `400` / `500` / `600` | body / labels and headings / emphasis |

Five sizes, three weights, no italics except the `shared` placeholder in an inherited matrix
cell. The scale is small on purpose: this screen's job is to fit a whole run in one view, and
the existing components already settled on 13px.

The status glyphs are set in `--font-mono`, not `--font-ui`. Two reasons: the mono stack has
reliable coverage of the glyph set, and identical advance width means every id in the step
list starts at the same x-position without a table.

### Space, shape, layout

| property | value | note |
|---|---|---|
| `--sp-1` … `--sp-8` | `2 4 6 8 12 16 24 32` px | everything; no other spacing values appear |
| `--r-1` / `--r-2` / `--r-3` | `2px` / `4px` / `6px` | chips and glyphs / controls / panes |
| `--bw` / `--bw-thick` | `1px` / `2px` | hairline and control borders / state borders and focus |
| `--rail` | `300px` | left column |
| `--header-h` | `48px` | app header min-height |
| `--measure` | `96ch` | prose max width. Payload blocks are exempt |

No shadow tokens. Elevation is a border plus a surface step, which survives both themes
without a second set of values; a shadow tuned for light looks like dirt on dark.

The one animation is `gh-pulse` on the running glyph, 1.4s opacity, disabled under
`prefers-reduced-motion: reduce`. Motion is never the only carrier of anything.

## Status semantics

Six statuses. Five come from `RunStatus` in `lib/store/runs.ts`
(`running | awaiting | interrupted | passed | failed`) and three from `StepStatus` in
`lib/engine/types.ts` (`passed | failed | skipped`); the union is six, and the same badge
renders both. That is the point of having one badge: a status in the step list, in the run
status line and in the earlier-runs list is the same word and the same shape.

| status | glyph | colour | shape | reads as |
|---|---|---|---|---|
| passed | `✓` | `--pass` | square, 1px border, tinted fill | done, fine |
| failed | `×` | `--fail` | square, **2px** border, tinted fill | done, not fine |
| skipped | `–` | `--fg-faint` | square, **dashed** border, no fill | never ran, on purpose |
| awaiting | `‖` | `--warn` | **circle**, 1px border, tinted fill | stopped, waiting for you |
| running | `>` | `--info` | **circle**, 1px border, tinted fill, pulsing | still moving |
| interrupted | `!` | `--halt` | square, **dotted** 2px border | stopped, not by you |

The shape language is the thing that survives greyscale: **round means the run is still
alive** (awaiting, running), **square means it is over** (passed, failed, interrupted), and
**broken borders mean nothing was sent** (dashed = skipped by design, dotted = interrupted by
accident). Colour is a third channel on top of glyph and shape, never the first.

Glyphs are single characters from a set the monospace stack covers everywhere: `✓` U+2713,
`×` U+00D7, `–` U+2013, `‖` U+2016, `>` U+003E, `!` U+0021. If `‖` ever proves unreliable,
`||` (two ASCII pipes) is the substitute; nothing else in the set has an alternative and
nothing else needs one.

Markup contract:

```html
<span class="st st--failed">
  <span class="st__glyph" aria-hidden="true">×</span>
  <span class="st__label">failed</span>
</span>
```

`.st__label` is the status word. **It is always in the DOM.** Where the layout has no room
for it — the step list, the earlier-runs list — it is `.visually-hidden`, not omitted. A
glyph alone is a shape to a sighted reader and nothing at all to a screen reader.

### How a step row composes

```html
<li>
  <button class="step" aria-current="true">
    <span class="st st--failed">…</span>      <!-- col 1: max-content -->
    <span class="step__id">save</span>         <!-- col 2: minmax(0,1fr), mono -->
    <span class="step__meta">                  <!-- col 3: max-content, tabular -->
      <span class="step__attempts">3×</span> 1.2s
    </span>
  </button>
</li>
```

Three columns, baseline-aligned. The whole row is the button, so the click target is the row
and the focus ring outlines the row. Selection is `aria-current="true"`, which drives both
the background and the bold id — one attribute, no `selected` class to keep in sync with it.

`.step__attempts` renders only when `RunStep.attempts > 1`, in `--warn`, because a step that
needed four tries to pass is not the same news as one that passed.

Two statuses are **derived, not stored.** `StepStatus` has no `awaiting` or `running` member
and should not gain one. The run screen already knows the run status and the length of
`results`, so:

- run status `awaiting` → the step at `results.length` renders as an `awaiting` row
- run status `running` → the step at `results.length` renders as a `running` row
- run status `interrupted` → no derived row; interrupted is shown on the run status line and
  in the earlier-runs list. A step that never started has no row

The derived row needs the step id, which means reading `caseSnapshot.steps` — which the run
screen should be reading anyway, since the spec is explicit that the log view reads the
snapshot rather than the live case. Until it does, the derived row can render with the
status and no id, and that is a visible gap rather than a wrong id.

## Screens

Four layouts. Three of them are the same shell.

The shell: `.app` (header row + body row) → `.app__header` (flex) → `.app__body`
(`grid-template-columns: var(--rail) minmax(0,1fr)`, or `.app__body--wide` for one column).
At 1280px the run screen gives the detail pane 908px, which is about 120 monospace
characters at `--fs-2` — wide enough that a pretty-printed JSON body does not wrap.

Header, left to right: wordmark, project picker, case picker, env picker with its guard chip,
the primary `run` button, then nav to `envs` and `cases` pushed right by `.spacer`. Project
first, env after — changing project changes the case list and the Envs screen, so it reads
outside-in.

Rail, top to bottom: the run block (status badge, seed, anchor, env, replay, copy markdown),
then the error slot, then the pause actions when they apply, then steps, then earlier runs.
Fixed order. A control never moves between states; it appears or it is absent.

Pane head: step id as `.pane__title`, the step's status badge with its label visible, then
`copy curl` and `raw log` pushed right.

**The evidence region is the centre of this design.** One bordered box, `--line-strong`, no
internal gaps: the request line, the body actually sent, and the origins list are three
sections of a single exhibit, sharing borders. The reason is the brief's reason — this is the
line that separates "the product sent the wrong payload" from "I mistyped a token" — and a
region that has to be believed cannot be laid out like a footnote under a body block.

Four things make it read as evidence:

1. **The origins list is inside the same box as the body**, directly beneath it, sharing its
   border. Nothing sits between them. You look at a value and its origin without moving your
   eyes to another card.
2. **Three grid columns, so every `←` lines up down the pane.** `minmax(8ch, max-content)` for
   the path, `2ch` for the arrow, `1fr` for the token. Alignment is what makes twelve rows
   scannable instead of read one at a time. Zebra striping on odd rows keeps long paths
   attached to their tokens.
3. **The token carries the weight, not the path.** Path in `--fg-muted`, token in `--fg` at
   `--fw-mid`. The reader's question is "what filled this?", so the answer gets the emphasis.
4. **Absence is stated, not implied.** A step with no tokens renders the region with
   `.evidence__none`: *"no tokens — every value here was written literally."* An empty list
   that disappears looks like a missing feature; this is a real answer, and it is the answer
   `literal by default` promises.

The unresolved-reference row, `.origin--missing`, is the payoff: `--fail-tint` background, a
2px `--fail` inset left bar, the arrow glyph swapped from `←` to `✗`, and the missing name
after the token. This is the row that says *the step was skipped and here is the exact
reference that skipped it* — the invariant that a skipped step names its reference, made
visible. Colour, glyph and position all change, so it survives greyscale.

Failures use the same inset-bar treatment in the assertions list (`.assert--failed`). Two
places, one visual idea: a 2px bar on the left edge of the row means *this is the thing that
went wrong*.

`.truncated` sits inside the evidence box above the body when `RawResponse.truncated` is set,
in `--warn-tint` with a `!` — a body cut at `MAX_BODY_BYTES` must never look like a complete
one.

Only the rail changes. The pane still shows the last completed step.

```
│ RUN                       │

│ anchor  2026-08-20T00:00Z │

│ │ [continue] [edit body]│ │

│ values it extracted,      │

│ STEPS                     │
│ ⟨✓⟩ presign        312ms  │
```

The hint is not decoration. A paused run is the one place live credentials touch storage;
`CLAUDE.md` says to say so plainly in any doc that touches it, and the screen where a run sits
waiting is where the sentence belongs. `edit body` is in the inventory as specced-but-unbuilt
and it opens the pane's body block as an editable monospace field — same box, same borders,
`.code` becomes a `textarea` with `.input--mono`. No modal.

### 4. Run view — case editor mode

Same shell, same three regions, same row geometry. The step list stops showing statuses and
starts being editable; the pane shows the selected step's declaration.

```
│ STEPS                  [+]│┌── pane ──────────────────────────────────────────┐
│ ⟨POST ⟩ presign           ││ presign                        [step detail mode] │
│ ⟨PUT  ⟩ upload            ││ id       [presign            ]                    │
```

grid. `always`, `pause` and `needs` show as `.tag--static` chips in the meta column, where
duration sits in run mode.

- `.table__rowhead` is sticky on the left, so variable names stay put while twelve env
  columns scroll. `thead th` is sticky on top for the same reason.
- Three cell states, three treatments: **set** is a normal input; **inherited** is a dashed
  `--line` border on `--surface-2` with an italic `shared` placeholder — dimmer than a value,
  because nothing was copied; **empty** is `.cell--empty` — 2px dashed `--fail` border,
  `--fail-tint` fill, placeholder `empty`, and a `!` marker element after the input.
- The `!` is an element in the markup, not CSS `content`, so it reaches a screen reader. Its
  `title`/`aria-label` is the word `empty`.
- The plain/secret toggle is `.cell__flag`, an `aria-pressed` button. Pressed means secret and
  paints `--halt`. A secret cell's input is empty with placeholder `*** set` or `not set`; it
  is never prefilled, because the browser is never given the value. **There is no reveal
  affordance and no place to add one** — the API does not send the value, so no button could
  show it even if one existed.
- Foot: the empty count, `.count--warn` when non-zero, followed by what the marker means.

## States each screen must handle

Nothing below gets a spinner. A spinner tells you the app is alive; these tell you what is
happening. `.empty`, `.note` and `.error` cover all of them.

### Run view

| state | rail | pane |
|---|---|---|
| first load, nothing run | pickers populated, `run` enabled, no run block, no steps | `.empty`: "pick a case and press run. nothing has been sent yet." |
| loading the file lists | pickers disabled, `run` disabled | same empty text |
| run starting | run block with `⟨> running⟩`, seed and anchor as soon as the POST returns | `.empty`: "waiting for the first step" |
| running, steps arriving | rows append; the derived `running` row sits at the end | last completed step, auto-selected |
| awaiting at a pause | pause actions + the credential hint | last completed step; `edit body` enabled |
| passed | `⟨✓ passed⟩`, replay + copy markdown | selected step, or the last one |
| failed | `⟨× failed⟩`, replay + copy markdown | **first failed step auto-selected**, not the last step. The first failure is the cause; the ones after it are consequences |
| interrupted | `⟨! interrupted⟩`, replay; a `.note` saying it will not resume by itself | last recorded step |
| pre-flight refusal (empty env var, `readonly` guard, `confirm` guard) | `.error` with the server's message, no run block, `run` still enabled | unchanged empty state |

| no earlier runs | the `EARLIER RUNS` label and list are both absent | — |
| run opened from history | identical to its terminal state, plus a `.note`: "opened from history. replay reads the case and env files as they are now." | selected step |

existing `page.tsx` copy already warns about: replay re-reads the files, resume does not.

## Rules a later screen must follow

Nine rules. They exist so screen five does not need a retrofit.

**Tables.** `.table` inside `.table-scroll`. Header cells uppercase `--fs-1` `--fg-muted` on
`--surface-2`, sticky top. Row separators `--line`, never a vertical grid. First column
sticky when the table scrolls sideways. Numeric columns right-aligned with
`font-variant-numeric: tabular-nums`. Totals and counts in `tfoot`, never floating above the
table.

**Inputs.** `.input`, or `.input--mono` when the content is a payload, a template, a path or
a key. Border `--line-strong` — not `--line`; a control's edge has to clear 3:1. Invalid is
`aria-invalid="true"`, which paints the border, never a colour class. Every input has a
label: `.field__label`, or `.visually-hidden` when the column head is the label.

**Buttons.** `.btn` is the default. `.btn--primary` is the solid one and there is **at most
one per screen region** — `run` on the run screen, `continue` at a pause. `.btn--ghost` for
inline text actions. `.btn--xs` for anything inside a pane head or a table row. Disabled is
the `disabled` attribute, never a class and never `pointer-events: none`, which also removes
the tooltip and the focus.

**Monospace blocks.** `.code`: `--surface-sunken`, `white-space: pre-wrap`,
`overflow-wrap: anywhere`, `max-height: 26em`, then scroll. A payload never stretches a pane
to the height of the document, and it never truncates without saying so. `.code--flush` when
it sits inside a bordered region and should share that border.

**Copy affordances.** A `.btn--xs` with a text label — `copy curl`, `copy markdown`. No icon,
because there is no icon package and a glyph nobody recognises is worse than four words. On
success the label becomes `copied` and `data-copied="true"` for about 1.2s, which paints it
`--pass`. Never a toast. Copy buttons live at the level they copy: run-level in a pane head,
step-level in the step's own row or pane head.

**Status.** Always the `.st` badge. Never a bare coloured dot, never colour on the text alone.
The label is in the DOM even when it is hidden.

**Secrets.** A secret is `***` or `*** set`, and nothing anywhere reveals one. When designing
a new screen: if a control would need the plaintext to work, the control is wrong, not the
rule.

**Focus.** `:focus-visible` gives every interactive element a 2px `--focus` outline at 2px
offset, globally. Do not remove it, do not replace it with a border change, do not scope it
away. When a whole row is clickable, the row is the button, so the ring outlines the row.

**Colour is never alone.** Every state that means something carries a glyph, a shape, a border
style or a word in addition to its colour. The test: screenshot it, desaturate it, and see
whether it still reads.

## What I deliberately did not design

- **Mobile and tablet.** Out of scope by the brief. The layout is a two-column grid with one
  breakpoint's worth of tokens; a later pass collapses `.app__body` to one column and un-sticks
  the matrix. Nothing here blocks that.
- **A manual light/dark switch.** `prefers-color-scheme` was what was asked for, and a switch
  means a persisted preference, a `data-theme` attribute and a flash-of-wrong-theme problem on
  first paint. When it is wanted, the token blocks move behind `[data-theme]` and no other rule
  changes.
- **The authoring conversation.** The footer slot is reserved and named; message bubbles, a
  streaming indicator and a step-proposal form are not designed, because the feature is listed
  as deliberately absent in `CLAUDE.md`. See departure 1.
- **Step reordering in editor mode.** Drag-and-drop is a dependency or a day of work, and it is
  not in the inventory. The editor list is selectable, not sortable.
- **A distinct treatment for `semantic` assertions.** `AssertResult` is
  `{ expr, ok, detail }` with no field saying who judged it, so a badge marking LLM verdicts
  would be inventing data. The assertion row is the same either way. If the field arrives, it
  is a `.tag--static` chip in the row, no new layout.
- **Empty, loading and error illustrations.** A sentence that names the missing thing and the
  directory it should be in is more use than a graphic, and it costs no bytes.
- **Toasts, modals, tooltips and dropdown menus.** Not one of the screens needs a layer above
  the page. `edit body` edits in place, errors appear where the failure was, and every menu on
  these screens is a native `<select>` that themes itself. The first feature that genuinely
  needs a layer should design one; three screens do not.
- **Print styles, `@container` queries, view transitions.** No reader asked for any of them.
